# Interview Log — yttri-forge

## 2026-08-24 · Session 1

### Brain dump (источник: рабочая сессия бенчмарков candle vs llama.cpp)

- Проблема: стек Yttri потребляет GGUF и кванты llama.cpp, ядра портируются из
  llama.cpp → структурное отставание ×1.10–1.30 декод, ×1.3 префилл.
- Видение: свой конвейер BASE(safetensors) → собственный формат → собственные
  ядра. Этапы: (1) гибрид GGUF+F16-сайдкар per-tensor override, (2) W4A16/W8A8
  tensor cores для префилла, (3) полный собственный формат + своя калибровка.
- Факты: декод bandwidth-bound (меньше бит = быстрее), префилл compute-bound
  (tensor cores >> integer MMQ), MTP-head F16 → выше acceptance.
- Целевые модели: Qwen3.5-4B, Qwen3.8-27B (DeltaNet-гибриды).
- Железо: RTX 3060 12GB сейчас; аренда RTX 6000 Ada 48GB после успешных тестов.
- Ограничения: один разработчик, приватный репозиторий, интеграция без революции,
  GGUF остаётся fallback.
- Замерки-обоснование: см. qwen36-server docs/plans/2026-08-24-qwen35-4b-benchmark.md

### Q: Мультимодальность поддерживать в новом формате?

**A: ДА.** Vision/mmproj тензоры должны быть гражданами первого класса формата
(модель Qwen3.5/3.8 мультимодальная, mmproj-F32/BF16 уже в использовании).

### Q: Обратный конвертер?

**A: Не нужен.** Только прямая дорога BASE→наш формат.

### Q: Входные форматы?

**A: Только HF safetensors.**

### Q: Калибровка для этапа 2?

**A: Отложить** до W4A16-этапа.
