# План: закрытие 128k-паритета sm75 prefill (фазы A–E)

**Дата:** 2026-10-31. Источник: консультация Claude Opus 5.5 xhigh по коду проекта.


Основа: чтение кода. Команды и замеры ниже на стенде ещё не запускались.

**Порядок: A → B → D → C → E.** D идёт раньше C: иначе правка ядра обнулит дорогой OFF-прогон на 53 мин и нарушит условие Фазы 9 «один бинарник».

## Что в коде меняет исходные фазы

1. **«!»×20 пока не доказывает NaN.** `GreedySampler` (`model.rs:136-146`) вернёт 0 и при всех NaN, и при всех −Inf. Проверка уже есть: поле `finite` в `qwen35moe_logits.rs:74`.
2. **`qwen35moe_logits` не воспроизводит серверный путь.**
   - `prefill_chunk` вызывается одним куском (`:206`). OFF упрётся в `bail!` при T > 512 (`model_weights.rs:4593`).
   - `LOGITS_PROMPT_TOKENS` зацикливает фикстуру (`:178`), поэтому реалистичного текста нет.
   - Нужны цикл чанков и `LOGITS_PROMPT_FILE`.
3. **Пробник не покрывает 128k.**
   - Сверка `causal` идёт при kv0 ≤ 8191, `parity` — при kv0 ≤ 4113. C = 131072 есть только в `perf`, без сверки.
   - Режимов peaky/diffuse в коде нет, хотя журнал ссылается на «diff-режимы массы».
   - Данные `0.35·uniform` дают σ(S) ≈ 0.04, то есть почти плоский softmax.
4. **При конечных входах ядро переполниться не может.** `m ≥ m_ref − 40`, поэтому `l ≤ C·e⁴⁰ ≈ 3·10²²`. `O` и `l` масштабируются одним `corr`. Подозреваются нечисловые входы и усиление в ядре:
   - `:362`: S = +Inf даёт Inf−Inf = NaN, и `l` строки испорчен навсегда;
   - `:395`: P = 0 при V = NaN даёт NaN. Zero-fill (`:169`) закрывает только `tok ≥ k_end`, поэтому NaN из V текущего чанка попадает и в строки, которым токен не виден;
   - `:329`, `:362`: NaN в K молча превращается в нулевую массу и скрывает дефект.
5. **Счётчика только на выходе attention мало.** Нужны ещё входы Q/K/V и выход каждого блока, включая DeltaNet (30 слоёв из 40).
6. **Одного ON-прогона хватает вместо четырёх.** Префил причинный, поэтому один проход на 130k проходит все длины, а `[nan]` сразу даёт порог. 48k/64k/96k заменяет один контрольный прогон перед порогом.
7. **Цифре 383.7 т/с на 128k пока верить нельзя.** Это выше потолка дизайна 378 (§0.2) и оценки журнала 306. Неattention-часть выходит ≈ 2.30 мс против a = 2.65 мс. Причиной могут быть NaN-маршрутизация MoE или вырожденный промпт. По §6 журнала замер без совпадения greedy не доказан.
8. **Сброс O/l каждые 64 страницы (D) почти наверняка не нужен.** `m` и так перебазируется на каждой странице, а отношение O/l от масштаба не зависит.

## A. Закрепить промпт и найти первый NaN

- **Цель:** понять, NaN ли это, где он возникает и при каком kv0.
- **Файлы:**
  - `scripts/gen_long_prompt.py` (новый): `alpha`×N и реалистичный текст из `git archive <sha>`, плюс `prompts.sha256`;
  - перенос `/tmp/parity.py` и `/tmp/mike35.env` в `scripts/`, там же `PREFILL_CHUNK=512`: для Фазы 7 значение чанка в журнале не записано;
  - `bin/qwen35moe_logits.rs`: цикл чанков, `LOGITS_PROMPT_FILE`;
  - `real/model_weights.rs`: гейт `PREFILL_NAN_TRACE=1|abort` (`OnceLock`) в `forward_attn_prefill_paged_tree` на Q, K, V и выходе (`:4578`, `:4785`), плюс выход каждого блока в цикле префила;
  - при первом срабатывании: дамп Q, out, K/V-пула, таблицы и kv0 в safetensors (нужен для `replay` в B).
- **Измерить:** формат `[nan] start= layer= kind= nan= inf= row= head=`, поле `finite` на шагах 0–19, мс на чанк.
- **Прогоны (≈ 30 мин):**
  1. ON `alpha`×N, `prompt_tokens=130907`;
  2. ON реалистичный текст;
  3. контроль ON на чанк раньше порога.
- **Приёмка:**
  ```bash
  sha256sum -c prompts.sha256
  jq -c 'select(.type=="logits")|[.step,.finite,.argmax]' A/on_alpha.jsonl
  grep -m1 '^\[nan\]' A/on_alpha.err
  ```
  Фаза закрыта, когда выбрана одна строка таблицы:

| Наблюдение | Вывод | Дальше |
|---|---|---|
| Первый `kind=block` на DeltaNet, ядро до этого чистое | Источник вне ядра, ON лишь сдвинул траекторию | Проверить OFF на том же чанке; чинить источник |
| `kind=q/k/v` нечисловой на входе attention | Ядро получило плохие данные | Искать предыдущий блок по трассе |
| Входы конечны, `attn_out` с NaN | Дефект ядра | `replay` в B, затем D |
| Префил чист, `finite=0` с шага ≥ 1 | Декод-путь | Сверить состояние после ON и OFF |

- **Время:** 2–3 ч.
- **Риск:** средний, `alpha`×N может не воспроизвести «!».
- **При провале:** один прогон через сервер (`scripts/parity.py`, рестарт ~20 с) с тем же файлом. Не воспроизвелось — трижды ON на реалистичном тексте, а разовый «!» записать в журнал как невоспроизведённый.

## B. Расширить пробник

- **Цель:** ловить дефект без модели, за минуты.
- **Файлы:** `bin/prefill_sm75_probe.rs`:
  - `gen_vectors` (`:488`): режимы peaky (S с разрывами > 40 и > 88 между страницами) и diffuse;
  - режим **V≡1**: выход обязан быть ≈ 1. Тест `lse` этого не видит, потому что `l` считается до округления P (`:364`);
  - CPU-эталон на F64;
  - яд NaN/Inf в **видимой части** страницы (токен `kv0+q0+row+1`);
  - C ∈ {8k, 32k, 64k, 128k}, T = 128;
  - `replay <dump>`: ядро, decode-путь и F64 на дампе из A;
  - `:617`: WARN заменить на `bail!`.
- **Измерить:** `mean|Δ|`, `max|Δ|`, число NaN и `|Δlse|` от C, отдельно ядро против F64 и decode-путь против F64.
- **Приёмка:**
  ```bash
  cargo run --release -p qwen35-batch --features "$F" --bin prefill_sm75_probe -- parity --c 8192,32768,65536,131072 --data uniform,peaky,diffuse,one
  ```
  - Код выхода 0.
  - `mean|Δ| ≤ 5e-4`, `max|Δ| ≤ 5e-3`, NaN = 0.
  - `|Δlse| ≤ 0.005` (масса 0.5 %).
  - V≡1: `max|out−1| ≤ 5e-3`.
  - `replay` повторяет NaN из A либо снимает подозрение с ядра.
- **Время:** 3–4 ч, CPU-эталон на 128k ≈ секунды–десятки секунд на голову.
- **Риск:** средний. После `bail!` могут упасть уже зелёные случаи: журнал считает `parity` пройденным, но WARN ничего не останавливал. Яд в видимой части, вероятно, упадёт сразу (`:395`).
- **При провале:** сначала проверить, что точнее по F64 — ядро или decode-путь. Если хуже decode-путь, эталоном становится F64, а не OFF. `__expf` при аргументе < −88 проверить отдельным значением.

## D. Численные правки (только по замерам A/B)

- **Цель:** устранить причину, а не маскировать её. Санитайзер NaN вместо источника запрещён.
- **Файлы:** `candle-kernels/src/flash_prefill_sm75.cu`.
  1. **Источник NaN** из строки таблицы A: первым делом правка для S = +Inf (`:362`) и для 0·NaN (`:395`).
  2. **`l` из округлённого P (`:356-379`)**: только если V≡1 превысил порог. Считать `sum` из F16-значения с явным обнулением P < 2⁻¹⁴, как ведёт себя `mma`.
  3. **Сброс O/l**: только если ошибка против F64 растёт с C более чем вдвое между 32k и 128k и NaN нет. Дефолт — не делать.
- **Измерить:** тесты B, `ptxas`, производительность.
- **Приёмка:**
  ```bash
  PROBE="cargo run --release -p qwen35-batch --features $F --bin prefill_sm75_probe --"
  ```

  - `perf` на 128k: R ≥ 30 TFLOPS (сейчас 34.7).
  - ON 130k: ни одной строки `[nan]`.
  - Повторная greedy-сверка 505/16k/32k: 20/20 (OFF суммарно ≈ 7 мин).
- **Время:** 0–4 ч, 1–2 цикла сборки.
- **Риск:** высокий, любая правка ядра обнуляет прежний паритет.
- **При провале:** откат правки, порог из A становится `PREFILL_SM75_MAX_C`, переход к E.

- **Цель:** доказать паритет на финальном бинарнике, на реалистичном тексте.
- **Файлы:**
  - `bin/qwen35moe_compare.rs:44-46`: добавить `GATE_STRICT=1` (косинус ≥ 0.9999, `max|Δ|` ≤ 0.1), нынешние 0.997/1.3 слабее §7;

- **Приёмка:**
  ```bash

  PREFILL_SM75=1 qwen35moe_logits $GGUF 20 capital off.jsonl > forced.jsonl

    qwen35moe_compare --gate off.jsonl forced.jsonl
  jq -s '[.[]|select(.type=="tokens")|.ids]|.[0]==.[1]' off.jsonl on.jsonl   # true = 20/20
  ```

- **Время:** 30 мин кода и 1.5 ч стенда, `llama-server` ещё ≈ 30–60 мин.
- **Риск:** высокий, журнал §5g/§5m показывает чувствительность выдачи к малым отличиям.
- **При провале:**

## E. Решение и хвост Фазы 8

- **Цель:** включить ядро по умолчанию или ограничить его с записью причины.
- **Файлы:**
  - `real/flash_decode_cuda.rs:251`: `Err(_) => true`;
  - `real/model_weights.rs:4574`, `:4780`: условие `PREFILL_SM75_MAX_C`. C в этой функции не виден (`kv_len_host` при префиле не обновляется), поэтому передавать через поле `PagedModelCtx` из `adapter.rs:1710`;
  - `scheduler.rs:79`: при активном `MAX_C` дефолт чанка 512, иначе fallback упадёт на `:4593`;
  - журнал §7, статус дизайна.
- **Измерить (≈ 8 ч в ночь):**
  - ON 7 повторов на 505..128k: 128k ≈ 42 мин;
  - OFF 7 повторов до 16k, 3 на 32k, 128k берётся из C (отклонение от правила журнала записать: 7×53 мин не окупаются, гейт абсолютный по ON);
  - `PREFILL_CHUNK` 512/1024/2048 на 16k и 128k, по 3 повтора;

- **Приёмка:**
  - профиль без `PREFILL_SM75` на том же бинарнике: `python3 scripts/parity.py http://127.0.0.1:18099` даёт 20/20, три рестарта × два режима;

  - 505: ON ≥ OFF−3 % в одном прогоне. Абсолютный гейт 238 заменён: журнал показал, что он снят в другом термопрофиле, а цель §1.1 и так относительная;
  - 256k: `window=` в логе не меньше промпта, NaN = 0, greedy 20/20;
  - `cargo check -p qwen35-batch` и `--features cuda` без изменений.

| Итог гейтов | Решение |
|---|---|
| Всё прошло, включая 256k | Default ON |
| 128k прошёл, 256k нет или окно упало | Default ON, `PREFILL_SM75_MAX_C=131072` |
| 128k не прошёл, порог известен | Default ON, `MAX_C` = порог минус один чанк, чанк 512 |
| Паритет не прошёл на 16k/32k после D | Default OFF, запись причины в журнал |

- **Время:** 1 ч кода и ночь стенда.
- **Риск:** низкий для переключателя, средний для 256k (11 ГиБ могут сузить окно, а это тихое скольжение).
- **При провале:** откат одной строкой `:251`. `PREFILL_SM75=0` остаётся fallback.

**Итого:** ≈ 2 рабочих дня и одна ночь стенда. Если B покажет, что D не нужен, — на 3–4 ч меньше.
